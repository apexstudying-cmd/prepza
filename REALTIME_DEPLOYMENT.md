# Prepza realtime chat deployment

The realtime branch adds Socket.IO without changing the E2EE boundary. The Flask API still persists messages and the browser still encrypts/decrypts them.

## Render start command

For the service that currently runs the Flask app, use:

```text
gunicorn -k gthread -w 1 --threads 100 realtime_server:app
```

Do not increase the Gunicorn worker count while using the default in-memory Socket.IO room registry. When Prepza needs multiple instances, add a shared Socket.IO message queue (for example Redis/Valkey) before horizontal scaling.

## What happens when a student is offline

The database remains the source of truth. A sender encrypts the message locally and the normal `/chats/<id>/messages` API stores the ciphertext. Socket.IO only broadcasts that ciphertext to currently connected room members. An offline student receives the message from normal chat history after reconnecting/opening the conversation.

## Security boundary

- Private E2EE keys never enter the server.
- Socket.IO never receives plaintext generated by the client chat UI.
- Room joins are authenticated and checked against `conversation_participant`.
- Typing and read events contain no message body.
